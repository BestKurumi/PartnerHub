# 客户绑定与范围规格

## Purpose

规定客户与不同平台身份关系的维护和查询行为，确保事件重放、冲突绑定、旧身份解绑及缓存故障不会被误解释为新的客户范围，允许明确约束内的最终一致性并保留可审计的事件处理结果。

## ADDED Requirements

### Requirement: 按平台维护客户唯一有效身份
中台 MUST 按客户×平台维护独立关系，支持BIND/UNBIND并保存事件结果；同UID重复绑定不变，不同UID绑定冲突保留原关系，只有匹配当前UID的解绑才改变关系。事件按分区处理次序裁决，不按 occurredAt 重新排序。

#### Scenario: 同一客户绑定两个平台
- **WHEN** A和B分别为同一客户提交不同UID的合法绑定事件并消费生效
- **THEN** 权威关系包含两个独立身份，路由按各平台UID创建目标

#### Scenario: 冲突绑定和旧UID解绑
- **WHEN** 当前A绑定U1后收到BIND U2，或当前绑定U2后收到UNBIND U1
- **THEN** 分别记录CONFLICT或UID_MISMATCH，保持当前关系不变

### Requirement: 重放不重复改变已裁决关系
中台 MUST 按 eventId 及内容识别同次事件；相同内容复用结果，不同内容记录冲突。事件结果和关系变更 MUST 同事务，提交成功后才允许推进连续消费位点；重放旧BIND不得在后续解绑后复活关系。

#### Scenario: 已解绑后重放旧绑定
- **WHEN** BIND事件已成功，随后UNBIND生效，再重放原BIND eventId及内容
- **THEN** 返回旧事件处理结果，权威关系仍为未绑定

#### Scenario: 数据库失败和毒消息
- **WHEN** 事件持久化失败，或遇到格式错误/同ID不同内容消息
- **THEN** 数据库失败不得提交消费位点；毒消息仅在异常已持久保存后才可跳过，保存失败继续保留处理责任

### Requirement: 完整缓存结果与有界权威回源
关系查询 MUST 返回完整目标快照、成功查库的明确空结果或查询错误。缓存缺键/损坏/不可用 MUST 不等价于无绑定；回源 MUST 有超时、并发/速率限制及同客户合并。缓存最终一致，正/空快照TTL和过期采样按设计 §6.1。

#### Scenario: 缓存未命中但数据库有绑定
- **WHEN** 客户缓存不存在且 MySQL 查询成功找到A/B关系
- **THEN** 返回全部有效目标并有界回填，不遗漏任何平台

#### Scenario: 空关系与数据库故障
- **WHEN** MySQL成功查询为空，或回源失败/预算耗尽
- **THEN** 前者返回明确空快照，后者返回查询错误；故障不产生NO_ROUTE假象

### Requirement: 固定平台身份及消费缺口可见
绑定事件 MUST 使用设计 §6 的 Demo 字段与固定平台身份；未知平台或身份冒充不得改变关系。首次消费组从earliest读取，既有位点越过保留窗口 MUST 停止并报告缺口，不静默跳至latest。

#### Scenario: 平台身份冒充与保留缺口
- **WHEN** A的Mock试图发布B身份事件，或现有消费位点已不可恢复
- **THEN** 前者拒绝且不改变绑定，后者报告缺口并停止相应消费，不伪装范围已完整恢复
