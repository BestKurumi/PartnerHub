# MVP 开发承接设计

## Context

开发动机与范围见 [proposal.md](./proposal.md)。完整架构、接口、数据模型、时序、参数与取舍唯一依据为[已确认 design.md v2.0](../2026-10-22-partner-hub-technical-design/design.md)；本文件仅记录开发承接和测试顺序，不复制或替代该正式方案。

归档设计交付提交 e3dc204；原设计任务全部完成仅代表文档交付。当前项目尚无Go应用/业务测试，既有SQL/Compose/监控为待校正草案，不作为已实现证据。本轮复用需求v1.9、权威协议及确认摘要，按用户要求不重做访谈。

## Goals / Non-Goals

Goals：将七项业务规格落实为可观察行为，按S1正常闭环、S2恢复、S3工程化、S4实测推进。每个切片同时具备行为测试、所需最小运行设施和实际验证；最终完整MVP统一验收。

Non-Goals：不重开已有架构取舍，不把“先做正常”解释为缩减全部MVP范围，不建设协议未规定的业务去重或真实平台身份工程。业务边界见proposal，不另立第二套规格。

## Decisions

### 继承正式技术决策

| 主题 | 唯一详细依据 | 开发约束 |
|---|---|---|
| 模块、依赖与应用生命周期 | v2.0 §2～§3、§13 | Go/Gin模块化单体，两个hub运行同程序；按需添加窄接口与基础设施 |
| 首轮、暂存、事务移交 | §4～§5、§7 | 直接首发；正常/异常只选择一条保存路径；未确认不伪造接管 |
| 关系、缓存与Kafka职责 | §6 | 绑定输入与平台2输出，取消旧成交入口通道；MySQL权威、有界回源 |
| UID、有限恢复及人工操作 | §7～§8 | 已定目标不重路由；owner/version/租约与命令一致性沿用 |
| 外发与Mock数据 | §9～§11 | 严格8字段，平台1秒/平台2毫秒，实际接收与中台状态分别存储 |
| 容量、指标与验收 | §12～§18 | 参数为可配置初值，单节点边界和全输入时延口径不扩张 |

已排除的替代方案：不恢复旧Kafka-first、成交防重/首发锁，不用Mock适应中台错误字段，不把业务重试放进Adapter，也不把MySQL任务表用于客户实际接收展示。这些均为既有确认结论，不是本轮新设计决定。

### 正常闭环优先的实现顺序

S1先通过协议/Adapter行为测试，随绑定、投递切片补最小Go/真实中间件测试入口，然后分别跑通HTTP平台和Kafka平台，最后聚合正常暂存/归档/查询及页面。无需先完成故障矩阵、完整监控或压测才看到业务结果。

S1尚未实现的异常路径必须明确未确认/拒绝，不允许用内存重试或空壳返回202假装已接管；S2再覆盖完整事务接管、恢复和人工命令，最终按全部规格验收。该中间开发状态不是MVP最终交付。

### TDD与测试边界

业务模型、字段适配、事件裁决、状态流转和异常修复先写最小行为测试，实际观察预期RED，再最小GREEN/REFACTOR；每个task保存真实命令与结果。纯部署/样式采用相应验证，不伪称TDD。

单元测试验证可观察结果而非只检查mock调用；真实MySQL/Redis/Kafka验证事务原子性、领取并发、归档、事件消费与Broker确认。端到端验收以两个Mock实际接收存储为证据；时延实验和故障演练另记录条件及未完成样本。外部服务相关检查不误标确定性local复用。

## Risks / Trade-offs

- [首轮结果尚未保存时退出] → 保持已确认风险，结果不明查询/人工核查；不擅加入口持久队列或自动重交。
- [外部收到而确认丢失] → UNKNOWN与有限恢复，保留重复可见性，不要求改协议去重。
- [旧草案与正式设计不一致] → 在相关业务切片中校正SQL/Compose/Topic/账号及监控，不把旧配置启动成功视为方案正确。
- [真实中间件受本机资源影响] → 单元测试与集成入口分层，记录实际依赖、资源和失败原因，未执行明确报告。
- [同一change包含多个阶段] → 以正常闭环先验收并持续更新权威tasks，后续仍需完整MVP验收，不提前归档。

## Migration Plan

仅本地Demo：锁定依赖版本，随业务切片引入可重复迁移与独立Mock schema/账号；一次性迁移后放行readiness。保留数据重启与显式重置分别验证。配置或schema回退先备份本地卷，不在服务启动中隐式删除数据。无生产迁移或真实平台发布。

## 可延后确认的实施事实

具体依赖补丁版本与机器可承载负载在Build锁定、报告；容量参数按v2.0初值测试调整。这些不改变当前业务规格或任务划分，不是重新访谈事项。

## 2026-10-26 已确认增量：四个控制台与运行观测

### 授权及基线

用户已通过交互原型 V2（源文件 `.superpowers/brainstorm/51452-1792983129/content/partner-console-v6.html`）确认布局、四独立入口、带文字的侧栏、Grafana 跳转和操作路径，并明确授权开发。本增量复用当前 change，不继承旧任务完成状态；原型数值均为示例，正式页面必须读取真实接口。旧的回归 PASS 只覆盖增量前实现，不作为新增能力已通过的证据。暂不归档、不提交、不推送；使用当前绑定的 main 工作区。

### 页面与数据职责

- 保留 `/hub/`、`/mock/upstream/`、`/mock/p1/`、`/mock/p2/`，共用浅色视觉组件，各自独立导航和状态。跨平台链接新标签打开，不作为登录角色切换；窄窗口仍显示菜单名称。
- 中台：总览、消息记录、单条链路、资源与中间件、诊断日志、客户绑定、待处理。消息与任务来自 MySQL 查询 API，绑定事件和人工命令仍沿用权威接口；不得在刷新或查询时触发投递。
- 上游：生成成交、测试记录、指引。A/B：消息中心、绑定管理、测试控制、指引。现有令牌、本机/同源、负载上限和不自动重交边界保留。原型故障选项只实施现有服务已支持场景，不增加协议行为。
- Grafana 保留现有 `hub-overview` 看板，中台提供可配置跳转。页面关键指标和 Grafana 共用 Prometheus；配置 URL 只能为 http/https，不嵌入密码、token，不允许页面控制后端目标或传入 PromQL。

### 指标与资源

新增受现有本地令牌保护的 `GET /hub/demo/ops/config` 和 `/hub/demo/ops/metrics?window=15m|1h|6h`，经 `/api/v1/ops/*` 分派。config 返回 `grafanaUrl`；metrics 返回 `sampledAt`、`window`、`metrics`，每项含 `key`、`source`、`status`（ok/unavailable/stale）、`samples`，sample 含 `labels`、`value`、`sampledAt`。缺失不能转成零；失败不清除上次成功样本，必须标出时效。

后台固定地址、白名单 PromQL、有界串行周期采样并缓存；HTTP 页面只读缓存。每次 Prometheus 请求有超时、响应大小与样本数量限制，不允许任意 URL/表达式；用户参数严格校验。固定键至少涵盖入口速率/拒绝、各平台首发结果和 P99、恢复数量、归档积压、绑定 lag、外部实收/B lag、逐实例 CPU/RSS/Go 堆/goroutine/GC 和数据库池。共享 Redis/恢复 gauge 使用 max，counter 按实例聚合，histogram 先合并 bucket 再求分位。指标不加入 msgId/traceId/UID 标签。

补充后台 MySQL 固定全局状态（连接、活跃线程、查询、慢查询、buffer pool）、Redis INFO（客户端、blocked、evicted、ops）、Kafka metadata（broker、partition、leader/ISR）；按成功时间与采样错误展示。仅使用既有最小服务身份，权限不足显示 unavailable，不授予 root/PROCESS 等宽泛权限。无宿主/node/JMX采集器的磁盘、容器限额和 Kafka JVM 显示未采集，不将配置上限冒充实际资源限制。后台循环纳入退出预算，不能因浏览器刷新探测依赖。

### 持久消息与全链路

消息列表补 `traceId` 和当前 `status` 的精确筛选（SUCCEEDED/RECOVERY_PENDING/NEEDS_ATTENTION/NO_ROUTE），与平台/客户/时间/游标共同限定。过滤必须在数据库 LIMIT 前生效，游标 scope 包含全部筛选；traceId 不唯一，返回所有匹配的分页记录。当前聚合状态沿用现有 pending 优先于 attention 的规则；有 attention 子任务的记录仍在待处理投递列表可见。

详情展示已有 receivedAt、routeSnapshot.resolvedAt、storedAt、首轮/当前平台状态、尝试起止/outcome/sendStarted/cycle 和人工操作。未存储的校验结束、Redis确认、HTTP响应完成时间显示未记录；storedAt 标注数据库插入时间。尝试使用现有有界分页，未知/截断明确说明。无目标不显示外发成功或补推操作。人工操作只允许既有合法状态，保留 operationId/operator/reason 和不明结果核查。

相关实收通过浏览器受保护的同源 Mock 查询入口，以平台、固定 UID、traceId 查询；中台不持 Mock DB 凭证。只能标为相关实收，不能唯一匹配某次尝试；B Broker ACK 和消费落库分开。HTTP404 暂无持久记录不等于未发送；查询503与空列表分开。

### 最近诊断记录

待处理完整性补充：消息 `routeStatus` 在数据库 LIMIT 前精确筛选且绑定游标，路由待人工列表不借助消息聚合 status，避免混合路由待人工与未完成投递导致漏项。这是已确认待人工范围内的边界完善。

独立有界线程安全环形缓冲，每实例最近 1000 条，重启清空；固定事件类型、白名单字段、截断长度，包含实例和 bootId。入口生成 requestId，记录校验拒绝、限流、保存未确认及异常首轮结果；后台关键错误纳入诊断。持久历史不改为此缓冲，不缓存完整请求/响应、凭据、UID或任意原始错误。仅解码成功后的 msgId/traceId 可用于诊断相关查询，非法请求体不为记录目的重新解码。

`GET /hub/demo/ops/diagnostics` 支持 level/instance/q/limit 的有界查询，返回 `items`、`instances`、`retention`。item 含 id/time/level/instance/bootId/kind/message、可选 requestId/msgId/traceId/deliveryId/platform/outcome/status；instances 含实例响应状态、容量和启动标识。查询失败和无匹配分别呈现，显示已返回实例与不可达实例，不以一个响应代表全体健康。实例之间只访问配置的固定私有地址和独立令牌保护的 `/internal/ops/diagnostics`，不能由参数指定地址；严格时间/大小/并发边界。只有查询范围内事实可见，提示重启/覆盖丢弃范围。

### 验证与回退

独立builder检查（2026-10-26）已关闭两项实施缺口：canonical `/api/v1/ops/*` 也必须本机/同源与令牌校验，不能借原只读API路径绕过；`deliveries` 增加 `currentState` 数据库精确筛选和游标绑定，待处理页分别列投递NEEDS_ATTENTION与路由NEEDS_ATTENTION，不能仅靠聚合消息状态。混合恢复/待人工场景必须验收。无新增用户决定。

业务筛选、诊断边界、聚合/采样失败和安全接口采用实际 RED→GREEN。样式和静态布局通过现有 Node 页面行为检查与浏览器验证；四平台逐菜单、刷新、跨页链接、绑定→成交→实收→链路、B暂停、拒绝和未确认、无指标/部分实例失败均需验收。最终运行相关 Go/race、真实依赖和部署浏览器回归，更新用户回归报告。保留旧实测历史，不把旧790条负载重标为本次执行。部署保留卷，回退旧二进制/页面和观测配置即可，不删除业务数据。

## 2026-10-27 中台人工验收展示修订

复用四页原型及接口契约，本次仅中台展示改良。指标卡片固定标题与采样状态，独立样本滚动区；观察窗口与刷新按钮底部对齐。指标表拆为“实例 / 采集对象”和“业务维度”，已知键值中文化并具名展示，保留未知键值和原始标签展开核对。“采样状态”表示 ok=采样正常、stale=样本已过期、unavailable=采样不可用，不代表业务成功；空样本单独显示暂无样本，不能显示零。

消息状态、首轮结果、路由、尝试、人工操作、绑定及待处理使用语义中文，保留原始枚举为提示/原始响应，未知值明确展示。平台投递一平台一行，显示平台名称、当前状态及固定UID（有值时）；消息路由单独具名，无明确routeStatus时显示未记录，不推断无路由。平台B发送成功说明仅Broker确认，不等于消费入库。

诊断表按“时间 / 级别 / 所属实例 / 事件与摘要 / 关联信息”组织，事件中文化；requestId/msgId/traceId/deliveryId分别标注、消息可查链路，平台与状态单独呈现。bootId等技术标识放可展开详情，长标识安全换行、不丢字段。共享CSS新增中台限定规则，不改变其他三页；API枚举、请求参数、权限、投递行为和持久化不变。

验证以受控响应的真实Chrome行为/几何断言覆盖密集样本滚动、按钮对齐、双平台混合状态、无路由、未知枚举/标签、中文绑定与待处理、诊断安全和技术信息完整。正式环境只读核实挂载、页面与既有查询，重建应用保持原Compose项目及命名卷。

### 2026-10-27 追加：消息列表折叠平台细节

用户要求列表默认缩略展示路由与投递结果，通过详情展开平台状态和固定UID。沿用当前DOM及中文映射：路由状态始终可见，平台结果按状态计数摘要（未知状态保留原值，未提供状态显示未记录）；原生details/summary作为“详情”按钮，默认关闭，展开显示现有各平台明细与B的Broker确认说明，再次点击收起。每行独立、键盘可用，展开仅切换已有数据不触发请求；无目标和未提供明细分别说明，不从缺失数据推断成功。

## 2026-10-30 待处理与人工恢复验收修订

投递列表分别展示投递任务编号 deliveryId、所属消息编号 msgId、中文平台和状态；路由列表仅展示消息编号。一个消息可对应多个平台投递任务。人工区按任务信息、操作人及修复原因、操作结果排列，按钮不承载长标识。恢复成功只表示新周期已保存，提供只读的消息链路进度入口；原始命令与响应折叠展示。

仅在结果未确认时显示“确认上次提交”，明确使用原 operationId 与原参数重新 POST，可能完成首次未保存的命令，并非只读查询。未确认期间锁定输入与新操作，切换查询不能替换原目标。确定性拒绝不提供盲重试，成功后旧快照操作保持禁用。保留原任务、固定 UID、尝试历史及后端接口语义；正式演示只做只读验证，保留卷滚动更新两实例。

## 2026-10-30 上下游展示验收修订

依据用户三张截图，仅修改上游测试记录、A/B接收卡片、B消费状态展示。沿用原有请求、单次提交和轮询语义。上游分列msgId/traceId，中文确认标签、提交时状态及HTTP分层，原始枚举/响应放详情；未知不映射成功。接收卡片保留双列，固定八字段按协议顺序显示，中文名＋次级原名＋值区域，元数据具名；未知字段额外显示，缺失显示未提供，值保留原始精度。B状态卡有文字和色彩，覆盖初始/加载/运行/暂停/未确认，失败清除旧确认结论；保留先读取再控制和不自动重发约束。无API、库表或投递逻辑修改。共享样式采用页面class限定，防止影响中台已验收布局。浏览器RED/GREEN及完整本地回归后，保留卷更新hub嵌入式页面及三个mock实例；不清卷，正式环境GET验收，不代用户生成成交或暂停消费者。
