# 外部合作中台技术方案设计提案

## Why

实习课题已经完成背景梳理、MVP 需求分析与 Grill Me 业务边界对齐，但尚缺少一套能指导后续开发、说明技术取舍并用于实习留档的正式技术方案。本 change 只交付设计文档，将已有共识转化为可审阅、可追溯的实现方案，不启动应用开发。

## What Changes

- 维护唯一正式技术方案 `design.md`，覆盖整个 MVP 的目标架构和首个闭环，不拆成三个开发 changes。原因是当前交付物是一套连贯设计，可靠性、观测与部署需要放在同一架构下推敲。
- 复用项目 `docs/` 目录的三份背景文档，不重复访谈已确认的需求。协议字段、枚举和外发限制以实习项目文档为最高依据。
- 说明直接首次投递、正常异步归档与 MySQL 异常接管的取舍、提交点和故障窗口；成交输入不重复由上游保证。
- 设计模块边界、数据模型、接口与事件契约、Adapter、路由与投递状态机、绑定缓存及受控回源、多实例任务恢复。
- 设计有限重试、人工兜底、平台隔离与容量边界，以及基于外部 Mock 实际接收记录的简单展示方案。
- 给出本地容器化、核心观测指标、后续业务测试/故障演练/压测的设计，以及正常闭环优先的开发切片建议。
- 复用用户已确认的完整方案形成正式设计结论；将协议事实、已确认业务约束、可配置初值及后续实测项清楚标注。

### 范围与非目标

本次允许修改设计文档、文档引用和 Comet/OpenSpec 必需元数据。用户另行授权的资料归集已将需求、选型、协议文档及配套图片移入项目 `docs/` 目录；Git 初始化和空提交仅用于恢复工作流。

本次不编写 Go/前端/Mock 业务代码，不修改 Compose、SQL、镜像或中间件配置，不启动服务，不执行业务压测，不把后续开发任务当成本次必须实现的事项。也不引入真实平台联调、接收端去重或中间件集群容灾。

## Capabilities

### New Capabilities

无。本次不增加或交付运行中的系统能力，仅沉淀技术方案，不能将文档中描述的未来能力标记为已实现。

### Modified Capabilities

无。没有运行时行为规格变更，`.openspec.yaml` 显式设置 `skip_specs: true`；不为通过校验虚构业务 delta spec。设计以既有需求分析和权威协议为输入，后续开发 change 再按批准的设计形成对应业务规格。

## Impact

- **文档位置**：本 change 下的 `proposal.md`、`design.md`、`tasks.md`；Comet 生成的上下文与审阅记录。设计细节只维护一份，其他产物引用它。
- **设计输入**：[需求分析 v1.9](../../../../外部合作中台-MVP需求分析.md)、[技术选型 v1.5](../../../../外部合作中台-技术选型调研.md)、[实习项目协议](../../../../实习项目文档-陈开鑫.md)。
- **现有环境**：Go 应用尚未实现；Compose、SQL、Nginx 和监控配置是既有草案，仅作为约束与差异调查输入，不视为正式方案。
- **外部影响**：本 change 不变更外部报文，不发布接口，不操作外部平台或生产数据。

### 设计完成与待实测项

已确认技术方案 v2.0，主链路、路由/状态、绑定缓存、消息契约、错误映射、并发恢复与查询展示统一见 design.md。参数仍待后续实施实测。已有技术栈和业务边界不再作为开放问题；文档不足以确定的外部协议内容必须标注为 Demo 假设，不能擅自补成真实规定。

### 文档验收场景

1. 读者能沿“绑定 → HTTP 成交校验 → 请求内路由/首发 → 两个平台投递 → 外部实际接收 → 各平台消息中心展示”追踪模块、数据和确认点；中台运维页单独查询状态、失败并人工重试。
2. 能解释上游保证成交输入不重复、中台直接首发，及正常无路由后再绑定也不补推的边界。
3. 能区分无有效绑定、缓存未命中、MySQL 查询失败，并找到有界回源与失败恢复方案。
4. 能区分正常异步归档、异常 MySQL 事务接管，分析外部确认与结果保存之间的退出窗口；说明外发重试仍可能重复。
5. 能核对绑定冲突、旧 UID 解绑、路由 UID 快照、单平台人工重试、永久错误与结果不确定的处理。
6. 能找到平台差异与敏感字段裁剪、实际接收展示、指标口径、本地部署，以及后续验证清单。
7. 文档链接有效、状态与术语一致；候选与已确认结论分开，不宣称测试、性能或服务运行结果已验证。
